Resumos: Reuniões Técnicas

Relatório de Resumo: Alinhamento Técnico CETAS Mobile IA

1. Objetivo da Reunião: Definir a estratégia de uma versão do sistema CETAS da plataforma web para uma solução mobile, priorizando a aceleração do processo de levantamento de requisitos e prototipagem através do uso de ferramentas de Inteligência Artificial (IA).

2. Panorama do Sistema Atual: O sistema CETAS já possui uma versão web em produção. Contudo, a demanda atual exige uma versão mobile construída do zero para atender profissionais em campo, integrando funcionalidades que hoje dependem de registros manuais para posterior transposição ao sistema.

3. Definições de Arquitetura e Tecnologia:

  • Ambiente de Desenvolvimento: Uso das IDEs Cursor AI e/ou Claude Code para codificação assistida.
  • Engenharia Reversa de Requisitos: Utilização do framework Playwright controlado por IA para varrer a aplicação web atual, mapear funcionalidades existentes e gerar especificações técnicas automaticamente.
  • Gestão de Código: Repositório privado no GitHub.
  • Autenticação: Integração com o sistema SCA2 do IBAMA para usuários internos e externos.

4. Escopo Definido para o MVP: Focado exclusivamente em operações de campo onde a mobilidade é crítica:

  • Login via SCA2.
  • Registro de Soltura: Funcionalidade principal em campo.
  • Geolocalização e Multimídia: Coleta de GPS e fotos/vídeos.
  • Modo Offline: Sincronização posterior de dados.
  • Monitoramento Pós-Soltura.

Nota Técnica: Funcionalidades administrativas e dashboards permanecerão na versão Web.

5. Desafios Identificados: Aprovação do Negócio, Infraestrutura (VPN) e Integrações Futuras (rastreamento por satélite/chips).

6. Matriz de Responsabilidades (Entrega 18/03): Roni (Mapeamento), Praxedes (Protótipos), Artur (Documentação), Bruno (Consolidação).

7. Próximos Passos: Reunião de Validação (18/03) e Apresentação ao Cliente.

Resumo Técnico – Reunião de Alinhamento APP CETAS (25/03/2026)

Participantes principais: Eduardo Praxedes, Alisson Wladmir, Felipe, Artur Silvestre, Bruno Rodrigues, Roni Cley.

1. Estrutura e Arquitetura: Mobile (React Native + TypeScript), DB Local (WatermelonDB ou SQLite), BFF (Node.js), Legacy Backend (IBAMA API). Arquitetura altamente refatorável pela IA.

2. Codificação Assistida por IA (25/03 a 01/04): Felipe inicia a codificação base (boilerplate) orientada por IA. Uso intencional do modelo "IA + revisão humana" (Felipe + Rodrigo revisor).

3. Requisitos e Protótipos: Especificações de Login, Pós-soltura e Soltura produzidas. Todo material servirá de prompt para IA.

4. Documentação: Site HTML já criado por Artur. Planejada a integração com repositório via CI/CD para atualização automática via IA.

5. Cronograma: Reunião com a área gestora (01/04/2026) para validação. Risco principal: mudança de escopo. Mitigação: adiantar desenvolvimento offline e usar IA para refatoração rápida.

Resumos: Pontos de Controle

Relatório Técnico – Reunião 1: Kick-off do Projeto APP CETAS (12/03/2026)

1. Objetivo Estratégico: Desenvolver 100% com IA um app mobile (Android/iOS) para o CETAS/IBAMA. Foco no MVP em 60 dias (prazo 11/05/2026). Trata-se de um piloto de transformação de paradigma na Administração Pública (ciclo AI-orchestrated).

2. Escopo do MVP: Funcionalidades core incluem Registro de Soltura (com GPS offline, fotos e sincronização) e Monitoramento Pós-Soltura. Requisitos obrigatórios: Offline-first, LGPD e Autenticação.

3. Paradigma AI-Driven Development: Zero código manual (na medida do possível). Uso de Figma AI, Cursor/Claude Code e Documentação como código. Stack alvo: Mobile + Backend IBAMA + Banco offline.

4. Organização e Papéis:
Grupo 1 (Discovery): Praxedes + Roni.
Grupo 2 (Engenharia): Allison + Felipe.
Sponsor: Bruno Rodrigues.

5. Próximos Passos: Sessão de Discovery profunda (17/03) e apresentação de wireframe + primeira versão de ADRs (19/03).

6. Riscos Técnicos: Limite de tokens da IA, integração com sistema legado, latência em campo e mudança cultural da equipe.

Relatório Técnico Resumido – APP CETAS (Exclusivo IA) (19/03/2026)

1. Objetivo: App nativo Android offline-first e Framework guiado por IA documentado.

2. Abordagem: Todo o ciclo é executado via agentes IA (Cursor + Claude). Time atua como orquestrador.

3. Ferramentas Planejadas: Playwright (engenharia reversa e testes), Cursor (prototipação HTML, geração mobile e documentação), GitHub Private (gestão).

4. Arquitetura do MVP: Android 8.0+ offline total, BFF para adaptação, reaproveitamento de serviços Java IBAMA e Data Lake intermediário. Dashboard fica apenas na Web.

5. Processos IA: Especialização de agentes por ADR, prototipação em tempo real, documentação automática no código e medição detalhada de tokens para custeio.

6. Decisões Críticas: Reaproveitamento 100% do backend atual, uso de HTML para protótipos navegáveis e suporte a polígono de soltura.
